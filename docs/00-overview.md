# 00 · 总览：目标、范围与术语

## 1. 背景

你想做一个 deepfake 生成、主动防御与检测的实验平台：

- 网页运行在本地，界面简洁；
- 图片、音频、视频、文字从本地上传；
- 生成与检测都在远端 GPU（AutoDL）完成，结果保存回本地；
- 生成任务要“多元化、多场景化”，平台按输入和模型特性自动路由到不同远端服务；
- 首个真实模型是已经验证效果不错的 Qwen3-TTS voice clone；
- 检测要给出“是否 deepfake 的可能性”，图片还要用框标出模型认为不合理的区域；
- 主动防御是对抗扰动 + 水印，保护本人素材。

GPU 型号（`ggg`）和完整模型清单（`abc`）尚未确定，所以本阶段先把**架构、接口、路由规则、数据模型、部署与验收**定下来。后续租好卡后按文档实施，不再返工设计。

## 2. 目标与非目标

### 本轮（P0）目标

1. 形成一套自洽、可施工的中文设计文档与 JSON 契约示例。
2. 明确三类能力在同一条“上传 → 远端推理 → 回传本地”链路上的行为。
3. 明确多模型自动路由的能力清单格式与决策算法。
4. 明确图片检测框的生成算法、可解释性边界和评估方式。
5. 明确主动防御的算法路线、验证指标和“不保证免疫”的局限。
6. 给出 AutoDL 部署、SSH 隧道、GPU 选型的决策表与运维手册。

### 非目标

- 本轮不写应用代码、不初始化依赖、不下载权重、不启动服务。
- 不做账号体系、多租户、计费、公网发布。
- 不做司法取证级鉴定；检测分数是模型输出，不是鉴定结论。
- 不提供对他人肖像/声音的未授权生成或“投毒”流程。

## 3. 用户故事

| 编号 | 故事 | 验收要点 |
|---|---|---|
| US-1 | 我上传自己的正面照 + 一段参考音频 + 想说的话，生成我的克隆配音 | 路由到 `audio.clone`，产物 WAV 可播放、可下载 |
| US-2 | 我上传一张照片和一段音频，生成说话视频 | 自动编排 TTS/唇形，产物 MP4 回传本地 |
| US-3 | 我上传一段视频和一张脸，做换脸 | 路由到换脸服务，返回 MP4 |
| US-4 | 我上传一张可疑图片，平台给出概率并在人脸/异常区域画框 | 返回 `verdict + score + regions[]` 和服务端叠加图 |
| US-5 | 我上传一段可疑视频/音频，平台给出时间轴与概率 | 视频抽帧聚合、音频分段 |
| US-6 | 我把自己的照片做成“免疫”版本再分享 | 返回保护图 + 证书，且平台自己的换脸链路效果下降 |
| US-7 | 我拿不准模型是否支持我的输入，平台告诉我缺什么、能换什么 | `422 NO_CAPABILITY` + 缺失角色 + 建议 |
| US-8 | 生成完想立刻检测一下效果 | 结果页一键“用此结果去检测”，串联演示 |

## 4. 角色与边界

| 角色 | 职责 | 信任边界 |
|---|---|---|
| 浏览器 SPA | 表单、上传、进度、结果展示、标注渲染 | 只信任本地 BFF |
| 本地 BFF | 校验、同意记录、文件落地、任务转发、SSE 中继、资产库 | 本机，持有远端 Token |
| 本地资产库 | 上传原件、生成物、检测报告、防御证书 | 本机磁盘，可删除 |
| 远端网关 | 认证、能力清单、路由、队列、文件收发 | AutoDL，半可信 |
| 模型服务 | 实际推理（TTS/视频/检测/防御） | AutoDL，进程隔离 |
| 运维人员（你） | 租卡、部署、隧道、模型更新 | 持有 SSH 与 Token |

## 5. 术语表（全文档统一）

| 术语 | 含义 |
|---|---|
| **Asset（资产）** | 一个已落盘文件及其元数据：`asset_id`、sha256、mime、时长/分辨率、来源（upload/generated）、本地路径 |
| **Role（输入角色）** | 文件在任务中的语义：`source_image`、`source_video`、`reference_audio`、`driving_audio`、`mask` |
| **Text 字段** | 文本不占文件角色：`text.target_text`、`text.reference_text`、`text.instruct` |
| **Capability（能力）** | 一个模型适配器声明的：支持哪些 task、需要哪些角色、限制、优先级、资源占用 |
| **Task（任务类型）** | 稳定 ID，如 `audio.clone`、`video.lipsync`、`detect.image`、`defend.image` |
| **Job（任务）** | 一次提交的执行实例，拥有状态机、进度、路由原因、输出 |
| **Route（路由）** | 从 task + 输入 + 约束选出模型的决策过程，结果写入 `route_reason` |
| **Artifact（产物）** | 任务输出文件：WAV/MP4/PNG/JSON 报告/叠加图/证书 |
| **Report（报告）** | 检测的结构化 JSON，含 verdict/score/regions/segments/模型投票/警告 |
| **Manifest（清单）** | 本地侧记录：输入哈希、模型与版本、参数、输出哈希、水印 ID、时间、同意记录 |
| **Consent（同意）** | 用户对“本人或已授权素材”的确认记录，任务提交前校验 |
| **Protection Cert（保护证书）** | 防御产物的可验证清单：水印 ID、扰动参数、指标、哈希、HMAC |
| **Modality（模态）** | `image` / `audio` / `video` / `text` |
| **P0–P6** | 实施阶段，见 [路线图](08-roadmap-and-acceptance.md) |

## 6. 已确认决策

| 编号 | 决策 | 依据 |
|---|---|---|
| D1 | 本地 Web + 本地 BFF，推理只在远端 | 本机无 Python/GPU；文件与任务留在本地 |
| D2 | 远端 FastAPI 网关 + 分模型工作进程 | 不同模型依赖与显存需求不同；符合“路由到不同服务” |
| D3 | 全部任务异步化，统一 Job 状态机 | 视频任务分钟级，需要进度与取消 |
| D4 | 文件先到本地，再由 BFF 转传远端；产物回传本地 | “保存到本地”，断线可重试 |
| D5 | 路由基于能力清单，不写死模型名 | 模型可以持续增加 |
| D6 | 图片框 = 人脸检测 + Grad-CAM/热区 + 连通域 | 分类器只给整图分数，需要可解释区域 |
| D7 | 生成物/防御物均写本地清单 | 可追溯、可复现、可验证 |
| D8 | 默认仅本机访问；远端 Token；SSH 隧道优先 | 演示阶段最小暴露面 |
| D9 | 主动防御 = 对抗扰动 + 水印 + 证书 | 你确认的方向 |
| D10 | 首个真实模型 Qwen3-TTS 1.7B Base | 你已验证效果；Apache-2.0 |

## 7. 设计原则

1. **本地优先**：能留在本机的（原件、任务记录、产物、清单）绝不只留在远端。
2. **模型无关**：新增模型只加一个适配器 + 一条能力声明，不改前端主流程。
3. **输入用角色表达**：同一段音频在不同任务里可以是 `reference_audio` 或 `driving_audio`，路由按角色判断。
4. **结论可解释**：检测给分数、投票、区域、警告；防御给指标、证书、局限。
5. **失败可诊断**：每个错误码都有 UI 文案、日志字段和用户可执行的下一步。
6. **安全默认值**：本机回环、Token、同意门、TTL、水印、审计。
7. **可渐进交付**：P1 用 mock 远端先把 UI 与契约跑通，再接真模型。

## 8. 演示成功标准（P6 验收总目标）

- 生成：用自己的素材完成一次音频克隆、一次说话视频、一次换脸，产物均落本地并可播放。
- 检测：对自建 60 张图片集（30 真/30 假）给出概率与红框；对 10 段视频/音频给出时间线。
- 防御：保护图在平台自己的换脸链路中身份相似度明显下降，且水印可验证。
- 路由：故意缺 `reference_text`、超长音频、模型离线，均返回明确错误与建议。
- 稳定性：连续 50 个任务无泄漏、无脏数据；隧道断开后 UI 明确提示并可重连。
- 安全：浏览器无法直接访问远端；未勾选同意无法提交；删除资产后本地与远端均不可再取。

## 9. 文档约定

- 任务 ID、角色名、错误码、端口在全套文档中唯一，新增必须同步更新 [02 契约](02-api-contracts.md)。
- 坐标一律为**归一化 `[x, y, w, h]`，基于已做 EXIF 旋转的显示图**，保留 4 位小数。
- 时间一律 ISO 8601 带时区；时长单位秒。
- 概率/分数统一 `0.0–1.0`，阈值显式返回。
- “必须 / 应当 / 可以”分别表示强约束 / 推荐 / 可选。
- 所有外部模型的能力与许可证以**部署时仓库 LICENSE 为准**，文档中的许可证状态需在 P2 前复核。
